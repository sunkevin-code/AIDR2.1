1. 产品定位与设计原则

01 / 12

AIDR（AI Dynamic Response）定位为 AI Agent 的主机侧运行时安全控制面，保护对象不是模型本身，而是 Agent 在真实主机上使用 Prompt、工具、MCP、文件、Shell 和网络资源时形成的行为链。

会话是安全边界

每个会话拥有 Prompt、任务目标、工具调用序列、有效策略、行为基线和 Decision Trace。

最小权限是动态的

策略由静态配置、当前任务意图和上下文共同生成，形成短期任务级能力边界。

决策必须可解释

规则、语义模型、策略解析、行为偏移和最终 verdict 以结构化追踪关联保存。

阻断必须有证据

阻断、告警、放行均形成事件记录，关联会话、Agent、工具、规则和风险依据。

失败要可控

语义模型不可用时可降级到本地规则；策略保存、签名、验证和回滚独立管理。

逐步接近 EDR

当前支持用户态传感器和执行器；内核前置阻断是后续 Minifilter/WFP 阶段。

适用场景

开发者工作站
保护 Codex、OpenCode 等 Agent 的文件修改、命令执行和网络访问。
企业 AI 工作台
为不同 Agent、工作区和任务配置不同权限边界，保留完整行为审计链。

5. 运行时防御链与行为图谱

05 / 12

先识别当前会话的意图和资源边界，再用实际工具、进程、文件和网络行为验证是否偏移，最后把决策和证据回写到会话图谱。

01 Prompt / Session

采集会话 ID、Agent、模型、工作区、Prompt 和上下文。

02 Intent

规则引擎先分析，语义模型补充目标、风险和能力。

03 Policy

叠加全局、工作区、Agent、会话边界。

04 Action

在 Hook 或传感器事件点做 allow、alert、block。

05 Drift / Audit

与基线比较，生成 Trace、事件和图谱。

行为图谱语义

节点

context会话/Prompt；intent意图和策略；tool工具/对象；decision最终决策；outputAgent 输出。

关系

contains、classifies、authorizes、invokes、enforces、returns 表达从请求到结果的因果路径。

典型阻断路径

UserPromptSubmit → local rules: sensitive_data + data_exfiltration → semantic model: high confidence / critical intent → policy resolution: explicit deny overrides allow → final verdict: block → hookSpecificOutput: deny → event + decisionTrace + session graph node
图谱不是日志替代品，而是把 Prompt、意图、策略、工具和决策放入同一条可审计上下文，回答“为什么放行/阻断”和“行为从哪里偏离”。

6. 策略模型与 Decision Trace

06 / 12

策略层级

Global

全局模式、默认能力和安全底线。

Workspace

目录、域名、MCP 工具和工作区边界。

Agent

Codex、OpenCode 等 Agent 能力覆盖。

Session

当前任务生成的短期有效策略。

Decision

allow、alert、block、approval。

冲突原则：显式 deny 优先；approval_required 优先于 allow；Agent 边界收敛于 Workspace，Workspace 收敛于 Global。

Decision Trace v1

字段作用示例
schemaVersion追踪结构版本aidr-decision-trace-v1
traceId关联 hook、事件和图谱UUID
sources规则、语义、策略解析、行为基线是否参与source flags
localRules规则分析器、规则名和本地 verdictrules.prompt_block
semanticModelProvider、Model、confidence、语义 verdictconfigured provider
sessionPolicy能力、审批要求和策略层级resolution layers
final最终 verdict、规则和原因block / reason

策略生命周期

Draft

由静态策略、任务意图和历史行为生成候选。

Validate

检查能力与路径冲突、允许/拒绝重叠、网络和 MCP 边界。

Sign / Activate

PolicyStore 生成 revision 和签名元数据，并更新运行时引擎。

Rollback

从历史 revision 恢复并重新验证，保留审计事件。

9. 安全设计与威胁防护

09 / 12

当前检测维度

Prompt Injection

检测忽略系统指令、读取凭据、改变安全边界等组合意图。

间接注入 / RAG 污染

检查工具和响应内容中的高风险指令和污染线索。

敏感数据外传

识别敏感路径、凭据材料、上传和疑似密钥输出。

恶意 URL

结合 URL、网络意图、域名边界和工具调用判断风险。

行为偏移

比较目标、能力、顺序和资源边界的会话偏差。

最小权限

限制文件、Shell、网络、MCP 和敏感操作审批。

决策优先级与执行现状

Fail-closed 边界：高置信度高风险 Prompt、工具调用或工具响应优先阻断；语义模型不可用时根据配置降级到规则或告警；显式拒绝覆盖允许。

已具备

用户态进程终止、Windows Firewall 管理规则、文件策略预检/隔离、事件审计和策略回滚。

尚未具备

Minifilter 文件 pre-operation、WFP pre-connect、进程创建前回调、正式抗篡改和驱动签名。

生产化必须补齐：正式代码签名、最小权限服务账户、密钥托管、集中式身份认证、Minifilter/WFP 驱动签名、升级包签名和安全审计。
